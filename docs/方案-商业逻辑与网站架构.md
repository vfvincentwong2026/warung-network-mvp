# Warung Network 商业逻辑与网站信息架构方案

> 版本：v1.0 ｜ 性质：开发基准文档（后续网站、数据系统、地推流程均以此为准）
> 仓库背景：https://github.com/vfvincentwong2026/warung-network-mvp

---

## 0. 一句话战略

**用最低成本的技术（地图 + 联系人数据库），把地推能力转化为可视化的签约网络资产，用它换取第一个付费品牌客户；品牌收入和数据积累到位后，再叠加 AI 动销与 SKU 选品服务。**

技术不是护城河，**签约网络的密度和店主关系**才是。技术投入控制在最小可用，资源优先砸地推。

## 1. 两阶段总体规划

### 第一阶段：网络构建 + 联系人体系（铺渠道）

**目标**：把物理网络变成可管理的数字资产，验证品牌方付费意愿。

| 子模块 | 内容 | 产出物 |
|---|---|---|
| 网络构建 | 按大学逐个突破签约 Warung：UI Depok → Gunadarma/PNJ（Depok 走廊顺路）→ UNJ → BINUS → 其余 | 签约漏斗实时数据 |
| 联系人体系 | 三层档案：店主层（姓名/WhatsApp/坐标/品类/状态/订单）、校园层（学生会/社团/校园代理）、品牌层（BD 联系人/意向等级） | Google Sheets 联系人库 |
| 网站 v1 | 三视角静态站（品牌方/投资方/店主），实时展示签约漏斗 | Cloudflare Pages 站点 |

**生死命题**：用真实增长的签约网络，换取 **≥1 个品牌同意以 15%-20% 佣金试合作**。

### 第二阶段：AI 动销方案 + SKU 梳理（变现）

**前提**：第一阶段跑出 4-8 周真实订单数据。无数据时"AI 动销"对投资方是减分项，有数据后是加分项。

| 子模块 | 内容 | 收入模式 |
|---|---|---|
| SKU 梳理 | SKU 三级分类：引流款（Indomie/冰茶，高频低毛利拉人头）、利润款（新品牌零食/功能饮料，品牌付佣金）、测试款（未进印尼新品，小范围试销） | 分销佣金 15%-25% |
| 场景化选品 | 按大学画像差异化（UI 学生 ≠ UIN 伊斯兰大学学生） | 选品咨询服务费 |
| AI 动销（先做） | 印尼语营销文案生成、促销组合策划（如"咖啡+炸物下午茶"）、品牌数据报告自动生成 | 报告订阅费 |
| AI 动销（后置） | 补货预测（历史销量+校园日历：考试周/开学季/斋月）、新品铺店推荐（按点位历史数据匹配 Top 20 店） | 市场进入项目制收费 |

## 2. 第一阶段核心机制：签约漏斗

### 2.1 漏斗定义

```
目标点位（灰色）— 公开信息/实地踩点录入，未接触
  → 已接触（蓝色）— 地推聊过，互留 WhatsApp
    → 洽谈中（橙色）— 有明确意向，谈合作条件
      → 已签约（绿色）— 完成签约，可接单
        → 活跃（绿色+脉冲动画）— 近 7 天有订单
```

### 2.2 为什么漏斗比"点位总数"重要

- 投资方不为技术买单，只看**绿点密度和增速**
- 漏斗同时证明**市场空间**（灰点规模）和**执行能力**（状态流转速度）
- 8 家真实签约 > 40 家演示数据。演示数据可以在开发期占位，但上线前必须替换为真实数据，并在页面标注数据更新日期

### 2.3 店主数据结构（Google Sheets 列设计）

| 字段 | 说明 | 示例 |
|---|---|---|
| id | 唯一编号 | W-UI-001 |
| name | 店名（印尼语） | Warung Bu Sari |
| university_id | 所属大学 | ui |
| lat / lng | 坐标（±1km 内） | -6.3628 / 106.8267 |
| categories | 品类（多选） | Indomie 煮面, 咖啡 |
| status | 漏斗状态 | target / contacted / negotiating / signed / active |
| owner_name | 店主姓名 | Bu Sari |
| whatsapp | 店主 WhatsApp | 62812xxxxxxxx |
| signed_date | 签约日期 | 2026-08-20 |
| weekly_orders | 近 7 天订单数 | 34 |
| notes | 地推备注 | 店主女儿管账，英文好 |
| last_visit | 最近拜访日期 | 2026-08-25 |
| photo_url | 门店照片（可选，增强可信度） | — |

### 2.4 地推工作流

1. 踩点：地推在 Google Sheets 移动端录入目标点位（灰点）
2. 拜访：聊完更新状态 + 备注
3. 签约：状态转绿，录入 WhatsApp，建店主档案
4. 网站每日读取 Sheets 数据重新渲染（或通过 Cloudflare Worker 定时拉取）
5. 周会看漏斗转化率，不看绝对数

## 3. 商业价值评估（决策依据）

### 3.1 利好

1. **细分市场聪明**：给 Warung 做 B2B 是印尼创业坟场（GudangAda/Ula 烧钱收缩，Bukalapak Mitra 收缩），但他们死于全印尼+全品类+压库存。本项目差异点：大学城窄场景、不压货、WhatsApp 原生零 App、资产轻。
2. **密度优势**：1 公里半径 20-30 家 Warung，一个地推一天跑 10 家，获客成本远低于分散社区。
3. **真实痛点**：印尼是快消必争市场，品牌新品上市测试、触达 Z 世代渠道是真实预算项。
4. **市场底盘**：300 万+ Warung，占印尼零售 68%。

### 3.2 风险

| 风险 | 应对 |
|---|---|
| 品牌方付费意愿未验证 | 第一阶段唯一 KPI：换 1 个试合作品牌 |
| 签约≠活跃（签约率 70% → 活跃率可能仅 30%） | 以"近 7 天有单"为活跃口径，对投资方只报活跃数 |
| 学生客单价低，C 端佣金是零花钱 | 收入重心放品牌侧（试销/陈列/数据报告） |
| AI 动销无数据支撑时像噱头 | 后置预测类功能，先做文案/报告生成 |

### 3.3 结论

**中等偏上，高度依赖执行速度。** 窗口期存在（大品牌找 Z 世代新渠道），但护城河是签约网络密度与店主关系。

## 4. 网站信息架构（v1）

### 4.1 定位

受众 = **品牌客户 + 投资方**。性质 = 招商展示 + 信任凭证，非内部工具、非 C 端下单平台。

### 4.2 三视角入口

| 视角 | 首屏内容 | 核心 CTA |
|---|---|---|
| 品牌方（默认首页） | 市场数据 → 实时网络地图（带漏斗）→ 合作模式 | WhatsApp 合作咨询 / 留资 |
| 投资方 | 增长数据（签约数周环比、活跃店主数）→ 单位经济 → 路线图 | 索取 BP / 约谈 |
| 店主（印尼语轻量页） | 零成本多赚钱 → 流程图 | WhatsApp 一键联系地推 |

### 4.3 页面结构（单页长滚动 + 店主子页）

1. **Hero**：品牌名 + 使命（让大学城 Warung 高峰时段多赚 20%）+ 双 CTA（看地图 / 合作咨询）
2. **数据亮点**：300 万+ Warung、68% 零售份额、覆盖大学数、已签约/活跃店数（**真实数据，来自 Sheets**）
3. **🗺️ Warung 城市地图**（核心模块）：
   - Leaflet + OpenStreetMap，视野覆盖 Jabodetabek
   - 大学大徽章 marker + Warung 小 marker（按漏斗状态着色，活跃店加脉冲动画）
   - 筛选：按大学 / 按状态；点击大学飞过去并统计周边点位
   - Warung popup：店名、品类、状态、（签约店显示）周订单数
   - 漏斗统计条：目标 N → 接触 N → 洽谈 N → 签约 N → 活跃 N
   - 标注数据更新日期，增强可信度
4. **运作流程**：学生扫码 → WhatsApp 下单 → QRIS 支付 → 店主备餐（4 步图）
5. **合作模式**：分销佣金 15-25% / 终端陈列 / 数据报告订阅 / 市场进入服务
6. **增长与路线图**：签约增长曲线 + Phase 1-4 时间线
7. **Footer**：联系（WhatsApp/Email）、GitHub、数据说明

### 4.4 技术方案

- **纯静态站**：HTML/CSS/JS + Leaflet 1.9（CDN），无构建步骤
- **数据源**：Google Sheets 发布为 CSV/JSON，前端定时拉取渲染；或构建期生成 `data.js`
- **部署**：Cloudflare Pages，连接 GitHub 仓库自动部署（构建命令空、输出目录 `/`）或 `npx wrangler pages deploy .`
- **原则**：第一阶段零后端。留资表单用 Cloudflare Pages Functions 或第三方表单服务，不自建后端
