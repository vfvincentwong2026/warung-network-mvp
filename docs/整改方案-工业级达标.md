# Warung Network 网站整改方案（工业级达标）

> 版本 v1.0 ｜ 2026-08-21 ｜ 依据：《审计-PM独立审计-2026-08-21.md》+ 工程审计报告（双审计组第四人独立视角）
> 审计基准：仓库 HEAD = 线上部署版本（md5 一致，结论对线上线下同时成立）

---

## 0. 总体判断

**工程质量超出 MVP 预期**（XSS 防线、CSV 解析器、降级链路、地图性能均过线），但有三类硬伤：

1. **转化终点断裂**——全站 35+ 个 CTA 指向占位 WhatsApp 号（真实陌生人的账号）和死链
2. **叙事诚信裂缝**——「签约 SKU」「实时数据」与同页漏斗 signed=2/active=1 互相打脸，投资人一点就穿
3. **基础设施裸奔**——软 404、无安全响应头、Leaflet 单点依赖、零工程护栏

P0+P1 全部闭环约 **30 小时**，分四批执行。

## 2. 第一批：诚信与口径（~4h，今天可做）

- 数字口径统一：map.lead「9 所大学城」→ 34（三语）；社群「34 个社群承接复购」改进行式「34 校社群招募中」
- 演示数据标识：Sheet 加载失败时地图显示黄色「演示数据 · 示例网络」角标；实时态绿色（恢复原设计意图）
- popup「近 7 天订单」演示值不得顶「实时数据」角标
- 宏观数据（市场规模等）补来源角标或删
- mitra 静态 HTML「每月固定收入」与软化后的 JS 字典对齐

## 3. 第二批：信息架构落地 sku.html（~8h）

按《审计-货盘信息架构.md》方案 B 执行：

- 新建 `sku.html`：44 SKU 全量（硬件 10 + 三餐 16 + 零食 18），类别锚点导航，三语
- 首页三板块合并为「首发货盘」橱窗：3 类别卡 × 3 精选 + 统计数字 + CTA 跳 sku.html
- 板块顺序重排：地图 → 战报 → 货盘橱窗 → 社群 → 档期 → 流程（问题→证据→报价→行动直线）
- nav 加「货盘」入口，两页互跳
- mitra FAQ 补店主真实 Top4：收入区间、陈列义务、退出机制、打款日
- 移动端导航 CTA 补位（汉堡菜单或悬浮按钮）；64vh 地图加手势提示
- 验收：首页首访图片 ≤500KB、移动端到 CTA ≤7 屏

## 4. 第三批：工业级基础设施（~10h）

| 项 | 内容 | 工时 |
|---|---|---|
| 软 404 修复 | 404.html + robots.txt + sitemap.xml | 2h |
| 安全响应头 | CSP/X-Frame-Options/Permissions-Policy 收进仓库 _headers，废弃控制台漂移配置 | 3h |
| Leaflet 本地化 | vendor 到 assets/vendor/（~150KB），消除 unpkg 单点；initMap 包 try/catch 防 i18n 级联死亡 | 2h |
| URL 白名单 | productUrl/image/whatsappGroup 统一 `^https://` 校验（对齐 wa.me 既有防御） | 1h |
| SEO 基础 | OG/Twitter Card + favicon + 静态双语 description | 2h |

## 5. 第四批：工程护栏（~6h）

- **预部署检查脚本**（零依赖 Node 脚本）：①两页 `?v=` 一致性 ②占位符扫描（6281234567890/xxx/TODO）③data.js 引用的图片全部存在 ④Sheet URL 200 可达 ⑤_headers 路径有效
- GitHub Actions 单 job：push 时跑检查脚本 + `node --check` 四个 JS
- 图片缓存键：data.js 图片路径加 `?v=` 或内容哈希（换图不再被 24h 缓存坑）
- P2 顺手包：WebP 转换（省 40%）、prefers-reduced-motion、--text-faint 对比度达标、CAT_I18N 枚举化、mitra 页卸载 1230 行 data.js
