# 产品审计：货盘信息架构（三餐 + 零食 + 硬件）

> 版本 v1.0 ｜ 2026-07 ｜ 审计人：PM ｜ 状态：待决策
> 触发：三餐与零食 SKU 全部堆在首页单页面，货盘规模已达 44 SKU

---

## 1. 现状实测数据

| 指标 | 数值 | 健康线 |
|---|---|---|
| 首页板块数 | **11 个**（hero→市场→地图→三餐→零食→社群→硬件→档期→流程→为什么→联系） | 6-8 |
| SKU 全展开展示 | **44 个品项全部平铺**（16 三餐 + 18 零食 + 10 硬件） | 橱窗 ≤12 |

## 2. 核心问题（按严重度）

### P1-1 货盘叙事被拦腰截断 🔴

板块顺序实测：`三餐(16) → 零食(18) → 【社群 34 校卡】 → 硬件(10)`

44 个 SKU 分散在 3 个不相邻的板块，中间被 34 张社群卡片隔断。投资人读到零食正进入「货盘心智」，突然被打断去看社群，再回来时货盘故事已经凉了。**"我们卖什么"应该是一个完整的故事单元，现在被切成了三段。**

### P1-2 首页过载，关键转化信息沉没 🔴

- 投资人首访：手机上滚 12-15 屏才到底部 CTA，中途流失率极高
- 28 张图 1.4MB + 523 个地图 marker，印尼 4G 环境下首访加载缓慢（虽有 lazy-load，DOM 本身已经很重）
- 首页同时服务三类受众（投资人/品牌客户/店主），每类都要穿过不属于自己的内容

### P2-1 三餐+零食 34 行小字列表，移动端阅读疲劳 🟡

meals 和 snacks 都是「分组 + 行式小列表」，连在一起 34 行，视觉上变成一堵文字墙。单个看都合格，连着看就是疲劳。

### P2-2 语言默认不一致 🟡

首页默认中文（受众=投资方/品牌方，正确），mitra 页默认印尼语（受众=店主，正确）——策略本身对，但两页语言偏好共用 localStorage key `warung-lang`，店主从 mitra 跳回首页会看到印尼语首页（内容面向投资人的），体验割裂。低优先级。

## 3. 方案对比

| | A. 最小调整（三板块挪相邻） | **B. 独立货盘页 sku.html（推荐）** | C. Tab 合并成一个板块 |
|---|---|---|---|
| 改动量 | 0.5 天 | 1-1.5 天 | 1 天 |

| 首页瘦身 | ❌ 28 图还在 | ✅ 首页只留 9 图橱窗 | ✅ |
| 可分享性 | ❌ | ✅ sku.html 直接发给品牌客户 | ❌ |
| 先例 | — | ✅ mitra.html 双页架构已验证 | — |
| SEO/招商 PDF 对齐 | 弱 | ✅ PDF 可印 sku.html 二维码 | 弱 |

## 4. 推荐方案 B 的具体设计

**首页 = 故事线（瘦身版）**
- 三餐/零食/硬件三板块合并为一个「签约货盘」橱窗板块：3 张类别卡，每卡 3 个精选品项带图 + 类别统计（"18 品项 · 对标 Kopiko/SilverQueen"）
- 底部 CTA「查看完整 44 SKU 货架 →」跳 sku.html
- 板块数 11 → 9，图片 28 → 9，移动端滚动深度减半
- 调整顺序：地图 → 漏斗战报 → **货盘橱窗** → 社群 → 档期 → 流程（叙事线：网络规模 → 卖什么 → 怎么触达 → 怎么合作）

**sku.html = 完整货架（新页）**
- 44 SKU 全量：硬件 10（大图卡）+ 三餐 16（4 时段）+ 零食 18（6 类带图）
- 顶部类别锚点导航（硬件/三餐/零食三段跳转）
- 三语切换，默认中文（受众=品牌方/投资方）
- 复用现有 snk-/sku- 样式体系与 i18n 机制，渲染函数基本平移

**为什么不做 C（Tab）**：44 个 SKU 的核心价值是「一眼看到规模」，tab 把 2/3 的货盘藏起来，违背初衷。

## 5. 验收标准

- 首页首访图片流量 ≤500KB（28 图 → 9 图 ≈ 450KB ✅）
- 首页移动端到 CTA ≤7 屏
- sku.html 三语零缺失、图片全量、注入安全过审计
- nav 加「货盘」入口（首页与 sku.html 互跳）
- 招商 PDF 与 sku.html 货盘保持一致（后续同步）

## 6. 风险与备注

- 移除首页全量 SKU 后，「货盘规模感」依赖橱窗卡片的数字传达——橱窗卡必须带品类统计数字（10/16/18）
- 零食 18 张图带电商水印的问题在 sku.html 同样存在，商用前需换图（另案处理）
- 占位运营号 6281234567890 仍未替换（第三次提醒）
